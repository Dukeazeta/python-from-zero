Two people walking towards each other

In real life

Two friends stand at opposite ends of a bridge and walk towards the middle, checking the railings as they go. When they meet, the whole bridge has been checked, and nobody walked it twice.

In this pattern, a pointer is just a variable holding an index. You keep two: left starting at 0 and right starting at the last index. Each step, you look at both items, do something, and move one or both pointers inwards. When they meet, you've visited every item once: O(n) time, and only two extra variables, so O(1) extra space.{{cite:1}}{{cite:3}}

shape.py
left, right = 0, len(items) - 1
while left < right:
    # look at items[left] and items[right]
    left += 1
    right -= 1

Changing a list directly, instead of building a new one, is called working in place.

LeetCode 344: Reverse String

Reverse the list of characters s in place (change the list itself; don't return anything) using two pointers and swaps.{{cite:4}} No [::-1] and no .reverse().

Stuck? A hint

The swap trick from Lesson 14 works on list items too: s[left], s[right] = s[right], s[left]. Do that, move both pointers, repeat while left < right.

Skipping what doesn't count

In Lesson 10 you checked palindromes by building a cleaned, reversed copy: O(n) extra memory. Two pointers do it with none. The twist in LeetCode 125: ignore everything that isn't a letter or digit, and ignore capitals. "A man, a plan, a canal: Panama" is a palindrome.{{cite:5}}

ch.isalnum() is True when a character is a letter or a digit.{{cite:2}} When a pointer is on a space or punctuation mark, move it past without comparing.

LeetCode 125: Valid Palindrome

Return True if s reads the same forwards and backwards, considering only letters and digits and ignoring case. Use two pointers, not a reversed copy.

Stuck? A hint

Inside while left < right: handle one situation per step with if / elif: left isn't alphanumeric, move left; right isn't, move right; lowercased characters differ, return False; otherwise move both.

When the list is sorted

In real life

Paying exactly 1,000 with one note and one coin from a tray sorted smallest to biggest. Try the smallest with the biggest. Too much? The biggest can't work with anything, so put it back. Too little? The smallest can't work with anything, so drop it. Each try rules one item out for good.

LeetCode 167 is Two Sum on a sorted list. Start pointers at both ends and add the two values. Too big: move right left to get a smaller number. Too small: move left right to get a bigger one. Equal: done. Each step rules out one number forever, so it's O(n) with no dictionary at all.{{cite:6}} Note this problem counts positions from 1, not 0.

LeetCode 167: Two Sum II

numbers is sorted from smallest to largest. Return the 1-based positions [index1, index2] of the two numbers that add up to target, using O(1) extra space.

Challenge: Container With Most Water

Each number is the height of a vertical line. Pick two lines; with the floor they make a container. The water it holds is the distance between them times the shorter line. Find the most water.{{cite:7}}

Start with the widest container (both ends). To possibly do better you must find a taller short side, so move the pointer at the shorter line inwards. Moving the taller one can never help: the width shrinks and the short side stays the limit.

LeetCode 11: Container With Most Water

Return the maximum amount of water. [1, 8, 6, 2, 5, 4, 8, 3, 7] gives 49 (lines at positions 1 and 8: width 7, height 7).

Stuck? A hint

Keep a best variable. Each step: work out the water for the current pair with min(), update best, then move whichever pointer has the shorter line.

Check yourself

From memory, without scrolling up. A wrong answer here costs nothing: you just pick again.

1. What extra space does Reverse String with two pointers use?

Swapping in place needs only the two pointer variables.

2. Two Sum II: the two pointed-at numbers add up to more than the target. What do you do?

The list is sorted, so moving right gives a smaller number and a smaller sum.

3. Why does Two Sum II's two-pointer trick need the list to be sorted?

Sorted order tells you which pointer to move. Unsorted, that decision means nothing.

4. What is "a1!".isalnum()?

It's True only if every character is a letter or digit; "!" is neither.
