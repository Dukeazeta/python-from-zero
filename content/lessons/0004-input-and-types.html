Programs that listen

In real life

A waiter comes to your table, asks "What would you like?", and waits. Whatever you say, they write it down on their notepad, word for word, and carry it to the kitchen.

The input() function is the waiter. It shows a question on the screen, pauses the program until the person types an answer and presses Enter, then hands back exactly what they typed.{{cite:1}} You store the answer in a variable:

order.py
food = input("What would you like? ")
print("One " + food + " coming up.")
Shows (the person typed jollof rice)What would you like? jollof rice One jollof rice coming up.

The text inside input( ) is the prompt: the question the person sees. End it with a space, so their answer doesn't touch the question mark.

In this course's exercises, the person's answers go in the Input box under the code: one line for each time input() asks a question. On your own computer, you type them in the terminal.

Every value has a type

In real life

Two coins in your hand can be added up. A price tag printed with "500" looks like a number, but it's ink on paper: you can read it, but you can't add two price tags together to get 1000. You'd have to read them and do the sum yourself.

Every value in Python has a type that says what kind of thing it is. The three you've met so far:{{cite:2}}

TypeShort forExamplesLike
intinteger: a whole number7, -3, 2000coins you can count
floatfloating-point: a number with a decimal point3.5, 5.0money with kobo or pence
strstring: text"hi", "500"words on a price tag

The type() function tells you a value's type. Try these in the Python shell from Lesson 2: type(7) shows <class 'int'>, type("7") shows <class 'str'>.

The input trap

input() always gives back a string, even when the person types digits.{{cite:4}} It's the price tag, not the coins:

trap.py
age = input("How old are you? ")
print(age + 1)
Shows (the person typed 21)How old are you? 21 TypeError: can only concatenate str (not "int") to str

age holds the string "21", and Python won't add a number to text. You saw this TypeError in Lesson 3.

Converting between types

Three functions turn a value into another type:{{cite:3}}

  • int("21") gives the whole number 21.
  • float("3.5") gives the decimal number 3.5.
  • str(21) gives the text "21" (you used this in Lesson 3).

So the fix is to convert the answer as soon as you get it: age = int(input("How old are you? ")). Python runs the inner part first (asks the question), then int() turns the answer into a number.

If the text isn't a whole number, int() can't convert it and you get a ValueError: ValueError: invalid literal for int() with base 10: 'twenty'. The value was the right type (a string) but the wrong content.

An easier way to fill in text

In real life

A form letter says "Dear ______, your order of ______ is ready." You don't rewrite the letter for each customer; you just fill in the blanks.

Joining strings with + and str() works, but gets messy. An f-string is a fill-in-the-blanks string: put the letter f just before the opening quote, and write any variable or expression inside curly braces { }. Python fills in the value, converting it to text for you.{{cite:5}}

letter.py
name = "Ada"
age = 21
print(f"Dear {name}, next year you'll be {age + 1}.")
ShowsDear Ada, next year you'll be 22.

No + and no str() needed: the f-string handles both. Forget the f, and Python prints the braces as they are: Dear {name}.... That's the most common f-string mistake.

New words

f-string
A string with f before the quote, where values in { } are filled in.

Try it: split the bill

2. What does print(int("42") + 1) show?

int("42") turns the text into the number 42, so adding 1 gives 43.

3. What does print(f"{2 + 3} apples") show?

In an f-string, Python works out what's inside the braces and fills in the result.
