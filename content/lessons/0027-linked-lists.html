A chain of nodes

In real life

A train where each carriage is only coupled to the one behind it. To reach carriage 8 you walk through carriages 1 to 7; there's no shortcut. But adding a new carriage at the front is quick: couple it on and call it the front. No other carriage has to move.

A linked list is a chain of nodes. Each node holds a value (val) and a link to the next node (next); the last node's next is None. You only hold on to the first node, called the head.{{cite:1}} LeetCode calls the node class ListNode.

chain.txt
head
 |
 v
[1 | next] -> [2 | next] -> [3 | next] -> None

Compared with a Python list:{{cite:2}} getting item number k means walking k steps, O(n). But adding at the front is O(1) (make a node whose next is the old head), where list.insert(0, x) is O(n). Interviewers mostly use linked lists to test whether you can move pointers around without losing the chain.

Walking the list, called traversal, always looks the same:

walk.py
cur = head
while cur is not None:
    print(cur.val)
    cur = cur.next

In the exercises below, a ListNode class and two helpers are already written for you (open "Already written for you" to see them): build([1, 2, 3]) makes a chain from a Python list, and to_list(head) turns a chain back into a Python list so the tests can compare.

Try it: count the nodes

Write length(head) that returns how many nodes are in the chain, by walking it.

Reversing a linked list

In real life

A line of people each pointing at the person ahead of them. To reverse the line, walk along it and turn each person round to point at the person who was behind them. You need to remember who was behind (so they can be pointed at) and who's next (so you don't lose the rest of the line when someone turns round).

Keep two pointers: prev (starts as None) and cur (starts at the head). At each node: save cur.next before you lose it, point cur.next back at prev, then move both one step forward. When cur runs off the end, prev is the new head. O(n) time, O(1) extra space.{{cite:3}}

steps.txt
start:   None   1 -> 2 -> 3
         prev   cur
step 1:  None <- 1    2 -> 3
                prev  cur
step 2:  None <- 1 <- 2    3
                      prev  cur
step 3:  None <- 1 <- 2 <- 3    None
                           prev  cur   -> return prev

LeetCode 206: Reverse Linked List

Reverse the list and return the new head.

Stuck? A hint

Inside while cur is not None: four lines, in this order: nxt = cur.next, cur.next = prev, prev = cur, cur = nxt.

Merging, with a dummy head

In real life

Building a chain of paper clips, it's awkward to start because there's nothing to hook the first clip onto. So you hang a spare clip on a nail first and build from that. At the end you take the chain off the spare.

LeetCode 21 merges two sorted linked lists into one, like the merge step of merge sort (Lesson 26).{{cite:4}} Building a new chain means "attach to the end of what you've built", but at the start there's no end to attach to. A dummy node solves it: make dummy = ListNode(), keep a tail pointer at the end of your chain, attach nodes to tail.next, and at the end return dummy.next.

LeetCode 21: Merge Two Sorted Lists

Merge list1 and list2 into one sorted list by re-linking their nodes, and return its head.

Stuck? A hint

While both lists have nodes: attach the smaller front node to tail.next, advance that list, then tail = tail.next. Afterwards, attach whichever list still has nodes: tail.next = list1 or list2 works because None counts as false.

Fast and slow pointers

In real life

Two runners start together; one runs twice as fast. On a straight track, when the fast one reaches the finish, the slow one is exactly halfway. On a circular track, the fast runner eventually laps the slow one and they meet again.

Move slow one node per step and fast two. Two classic uses:

  • The middle: when fast reaches the end, slow is in the middle (LeetCode 876).{{cite:5}}
  • Cycle detection: if a node's next points back to an earlier node, the list loops forever. If fast ever lands on the same node as slow, there's a cycle; if fast reaches None, there isn't (LeetCode 141, known as Floyd's algorithm).{{cite:6}} O(1) extra space, where a "seen" set would need O(n).

The loop condition protects you from stepping off the end: while fast is not None and fast.next is not None:.

LeetCode 876: Middle of the Linked List

Return the middle node. With two middles (an even number of nodes), return the second one.

LeetCode 141: Linked List Cycle

Return True if the list has a cycle. Use fast and slow pointers, O(1) extra space. (The setup's build_cycle(values, pos) links the last node back to position pos; -1 means no cycle.)

Comparing nodes: is

To ask "are these the very same node object?", use slow is fast. Two different nodes could hold the same value, so comparing .val isn't enough.

New words

Linked list
A chain of nodes, each holding a value and a link to the next.
Head
The first node of a linked list.
Dummy node
A placeholder node before the real start, making building a list simpler.
Fast and slow pointers
Two pointers moving at different speeds, to find the middle or a cycle.
is
Checks whether two names refer to the exact same object.

Check yourself

From memory, without scrolling up. A wrong answer here costs nothing: you just pick again.

1. What's the cost of getting the 1000th value of a linked list?

There's no index; you follow next links from the head.

2. Reversing a list, why save cur.next before changing it?

Once cur.next points backwards, nothing points to the remaining nodes unless you saved them.

3. When fast reaches the end, where is slow?

It has moved half as far.

4. What does the dummy node in Merge Two Sorted Lists give you?

With a dummy, every node, even the first, is attached the same way; you return dummy.next.
