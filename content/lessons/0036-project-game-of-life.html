Life, by four rules

In real life

Imagine a town where every house is either lived in or empty, and each night the same rules decide what happens: a lonely household moves out, an overcrowded one moves out, a comfortable one stays, and an empty house with exactly three neighbouring families attracts a new one. Run it night after night and surprisingly lifelike patterns appear.

Conway's Game of Life is a grid of cells, each alive (1) or dead (0). Every step, all cells update at once, based on how many of their 8 neighbours are alive:{{cite:1}}

  • A live cell with 0 or 1 live neighbours dies (underpopulation).
  • A live cell with 2 or 3 live neighbours stays alive.
  • A live cell with more than 3 live neighbours dies (overpopulation).
  • A dead cell with exactly 3 live neighbours becomes alive (reproduction).

This project comes from the Project Based Learning list, Robert Heaton's "Programming Projects for Advanced Beginners".{{cite:1}}{{cite:2}} His page breaks it into milestones; this lesson follows them, with tests for each piece. You already wrote the hardest part, live_neighbours, in Lesson 16; it's provided below so every exercise can use it.

Milestone 1: an empty board

Write dead_state(width, height) returning a board of height rows, each with width zeros. Each row must be its own list (remember the shared-row trap from Lesson 16).

Milestone 2: the rules for one cell

Write next_cell_value(cell, neighbours): given a cell's current value (0 or 1) and how many live neighbours it has, return its value in the next step, by the four rules above.

Milestone 3: the next board

All cells must update at the same time. If you change cells in the board while you're still counting neighbours on it, later cells see a half-updated board and get the wrong count. So build a brand-new board for the next step, reading only from the old one.

Two famous patterns make perfect tests. A 2 by 2 block never changes (a still life). A line of three, a blinker, flips between horizontal and vertical every step (an oscillator).{{cite:1}}

Milestone 3: next_board_state

Write next_board_state(board) returning a new board one step later. Use live_neighbours and next_cell_value (both already written for you above your code).

Milestone 4: render it as text

Write render(board) returning one string: each row on its own line, # for alive and . for dead. Rows are joined with "\n" (a new-line character) and there's no new line at the very end.

  2. Write life.py: paste in your dead_state, live_neighbours, next_cell_value, next_board_state and render, then add these at the bottom:

    life.py (the end)
    import random
import time


def random_state(width, height):
    board = dead_state(width, height)
    for r in range(height):
        for c in range(width):
            if random.random() < 0.3:     # about 30% of cells start alive
                board[r][c] = 1
    return board


def run(width=60, height=20, generations=200):
    board = random_state(width, height)
    for step in range(generations):
        print("\033[H\033[J", end="")    # clear the terminal screen
        print(render(board))
        print(f"Generation {step}")
        board = next_board_state(board)
        time.sleep(0.1)


if __name__ == "__main__":
    run()

    random.random() gives a decimal between 0 and 1, so it's below 0.3 about 30% of the time.{{cite:4}} time.sleep(0.1) pauses a tenth of a second between frames.{{cite:3}} The odd string "\033[H\033[J" is a special code that tells the terminal to clear the screen, so each frame replaces the last.

  3. Run it: {{py}} life.py. Patterns grow, collide and settle into blocks and blinkers. Press Ctrl + C to stop early.

Make it yours (pick at least one)

Heaton's page suggests extensions; they're what turns a tutorial into a portfolio piece.{{cite:1}}

  • Load a pattern from a file: read a text file of . and # into a board, so you can start from a glider or a "Gosper glider gun".
  • Wrap around the edges: make cells on the right edge neighbours of cells on the left, using % (Lesson 6) on the row and column.
  • Stop when stable: end the loop when the next board equals the current one, and print how many generations it took.

Check yourself

From memory, without scrolling up. A wrong answer here costs nothing: you just pick again.

1. A dead cell with 3 live neighbours. Next step?

Exactly three live neighbours is the reproduction rule.

2. Why build a new board instead of updating the old one cell by cell?

All cells must update together, based only on the previous step.

3. What is a blinker?

It's the simplest oscillator: horizontal, vertical, horizontal...

4. What's the Big O of one step on a w by h board?

Each of the w × h cells checks a fixed 8 neighbours.
