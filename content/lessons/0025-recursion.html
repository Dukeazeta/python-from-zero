A smaller copy of the same problem

In real life

You're in a long queue at the cinema and want to know your position. You ask the person in front: "what number are you?" They don't know either, so they ask the person in front of them, and so on, until the question reaches the first person, who just says "1". Then the answers travel back: "2", "3", ... until someone tells you, and you add one.

Recursion is when a function solves a problem by calling itself on a smaller version of the same problem.{{cite:1}} Every recursive function needs two parts:

  • a base case: a version so small the answer is obvious (the first person in the queue says "1"), and
  • a recursive case: do a little work and call yourself on something smaller (ask the person in front, then add one).
factorial.py
def factorial(n):
    if n == 0:                       # base case
        return 1
    return n * factorial(n - 1)      # recursive case

print(factorial(4))   # 4 * 3 * 2 * 1
Shows24

The textbook calls these the three laws of recursion: have a base case; move towards it on every call; call yourself.{{cite:2}} Break the second law (forget the - 1) and the calls never stop.

How Python keeps track: the call stack

In real life

Reading a book that says "see page 40", which says "see page 72". You keep a finger in each page so you can come back. When page 72 is done, you return to 40, finish it, then return to where you started. Your fingers form a stack: the last page you marked is the first you return to.

Each time a function is called, Python puts a stack frame on the call stack: a note holding that call's local variables and where to return to.{{cite:3}}{{cite:4}} For factorial(4), four frames pile up (4, 3, 2, 1) above the base case. Then they finish in reverse order, each multiplying the answer from below. It's a stack, just like Lesson 23.

unwinding.txt
factorial(4) = 4 * factorial(3)
               factorial(3) = 3 * factorial(2)
                              factorial(2) = 2 * factorial(1)
                                             factorial(1) = 1 * factorial(0)
                                                            factorial(0) = 1
                                             = 1
                              = 2
               = 6
= 24

The stack can't grow forever. Python stops at about 1,000 frames by default and raises RecursionError: maximum recursion depth exceeded.{{cite:5}} If you see that, your function almost certainly never reaches its base case.

Fibonacci, and a warning

In real life

Asking two friends to each work out half of a problem, and they each ask two friends, who each ask two more. The question spreads like a family tree, and most of those people end up working out the exact same sub-question as somebody else.

The Fibonacci numbers start 0, 1, and each next one is the sum of the two before: 0, 1, 1, 2, 3, 5, 8, 13... That definition is already recursive: fib(n) = fib(n - 1) + fib(n - 2), with base cases fib(0) = 0 and fib(1) = 1.{{cite:6}}

Written that way it's correct but very slow: each call makes two more calls, so the work roughly doubles with every step of n. That's exponential time, O(2ⁿ): fib(30) makes over a million calls, and fib(50) would take hours. The fix is to remember answers you've already worked out, which is the whole idea of dynamic programming in Lesson 33. For now, LeetCode only asks up to n = 30, so the plain version is accepted.

LeetCode 509: Fibonacci Number

Return the nth Fibonacci number using recursion.

Inside a class, call it as self.fib

A method calls another method (or itself) through self: self.fib(n - 1). Plain fib(n - 1) gives a NameError.

New words

Recursion
A function solving a problem by calling itself on a smaller version.
Base case
The smallest version, answered directly, which stops the calls.
Call stack
Python's stack of unfinished function calls, one frame per call.
RecursionError
The error when the call stack gets too deep, usually a missing base case.
Exponential time
Work that roughly doubles each time n grows by one, like O(2ⁿ).

Check yourself

From memory, without scrolling up. A wrong answer here costs nothing: you just pick again.

1. What stops a recursive function from calling itself forever?

The base case returns without calling itself again, so the calls can finish.

2. You see RecursionError: maximum recursion depth exceeded. Most likely cause?

Each call adds a frame; without reaching the base case, they pile up past the limit.

3. Why is plain recursive Fibonacci slow?

fib(n - 1) and fib(n - 2) both recompute the same smaller values again and again.

4. With def f(n): return 0 if n == 0 else n + f(n - 1), what is f(3)?

3 + 2 + 1 + 0. (This one-line form, A if condition else B, is called a conditional expression.)
