Do it once for each one

In real life

A teacher hands out exam papers: "for each student in the room, give them a paper." They don't keep checking a condition; they just go along the rows until every student has one. The list of students decides how many times it happens.

A for loop runs its block once for each item in a sequence. The simplest sequence is a range of numbers from range():{{cite:1}}

laps.py
for lap in range(3):
    print(f"Lap {lap}")
print("Race over")
ShowsLap 0 Lap 1 Lap 2 Race over

Each time round, the loop variable (lap here, but you choose the name) holds the next number. Notice range(3) gives 0, 1, 2: it starts at 0 and stops before 3.{{cite:3}} Three numbers, but the 3 itself is never included.

Choosing where range starts, stops and steps

You writeYou getMeaning
range(5)0 1 2 3 4stop before 5
range(1, 6)1 2 3 4 5start at 1, stop before 6
range(0, 10, 2)0 2 4 6 8count up in steps of 2
range(5, 0, -1)5 4 3 2 1count down

To count from 1 to n, write range(1, n + 1).{{cite:2}} Forget the + 1 and the loop runs one time too few. A loop that runs one time too many or too few is called an off-by-one error, and it's worth checking for every time you write a range.

while or for?

Anything a for loop does, a while loop with a counter can do too.{{cite:1}} Use for when you know what you're going through (5 times, every letter, every item). Use while when you're waiting for something to change (the right password, a price of 0).

New words

for loop
A loop that runs once for each item in a sequence.
Loop variable
The name that holds the current item each time round, like lap.
Off-by-one error

You want 1 to 10, so the range starts at 1 and stops before 11: range(1, 11).

The accumulator: building up a result

In real life

Counting the money in a tip jar: you start at zero, pick up each coin, add it to the amount in your head, and keep going. At the end, the number in your head is the total.

That's the accumulator pattern: start a variable at 0 before the loop, add to it inside the loop, use it after the loop.

sum_to_100.py
total = 0
for n in range(1, 101):
    total += n
print(total)
Shows5050

A close cousin is the counting pattern: start at 0 and add 1 only when something is true. For example, count how many numbers from 1 to 100 are divisible by 7: if n % 7 == 0: count += 1.

Try it: add up the even numbers

Ask Up to? and print the sum of all the even numbers from 1 up to and including that number. For 10 that's 2 + 4 + 6 + 8 + 10, so it prints 30.

Two ways to do it

Either loop over every number and only add the even ones (if n % 2 == 0), or let range do the work with a step of 2: range(2, limit + 1, 2). Both are fine.

Looping over a string

In real life

Proofreading a word letter by letter: you point at the first letter, check it, move your finger to the next, and so on to the end.

A string is a sequence of characters, so a for loop can go through it one character at a time:{{cite:4}}

spell.py
for letter in "Ada":
    print(letter)
ShowsA d a

FizzBuzz

FizzBuzz is a classic beginner programming test, and it's also LeetCode problem 412. You have every tool it needs: a loop, %, and if / elif in the right order.

Try it: FizzBuzz from 1 to 15

Print the numbers 1 to 15, one per line, but print Fizz instead of numbers divisible by 3, Buzz instead of numbers divisible by 5, and FizzBuzz for numbers divisible by both.

If 15 says Fizz

Only the first true check runs (Lesson 5). 15 is divisible by 3, so if that check comes first, Python never reaches FizzBuzz. Which check has to come first?

Check yourself

From memory, without scrolling up. A wrong answer here costs nothing: you just pick again.

1. Which numbers does range(2, 6) give?

range starts at the first number and stops before the second.

2. Which range counts from 1 to 10, including 10?

The stop value is never included, so to reach 10 you stop before 11.

3. In the accumulator pattern, where does total = 0 go?

Inside the loop, it would reset to 0 every time round and you'd lose the running total.

4. You want to keep asking until someone types quit. Which loop fits best?

You don't know how many times in advance; you're waiting for something to change.
