Blueprints and the things made from them

In real life

A cookie cutter isn't a cookie. It's the shape you use to make as many cookies as you like. Each cookie is separate: you can put icing on one without changing the others, but they all share the same shape.

A class is the cookie cutter: a blueprint describing what data a kind of thing holds and what it can do. An object (also called an instance) is one cookie made from it.{{cite:1}} You've used objects already: every string is an object of the class str, which is why it has methods like .upper().

pets.py
class Dog:
    def __init__(self, name):
        self.name = name
        self.tricks = []

    def learn(self, trick):
        self.tricks.append(trick)

    def show_off(self):
        return f"{self.name} can: {', '.join(self.tricks)}"

rex = Dog("Rex")
bella = Dog("Bella")
rex.learn("sit")
rex.learn("roll over")
print(rex.show_off())
print(len(bella.tricks))
ShowsRex can: sit, roll over 0

Taking it apart

  • class Dog: starts the blueprint. Class names use CapitalisedWords by convention.
  • Dog("Rex") makes a new object. Python then runs __init__ (two underscores each side, said "dunder init") to set it up.{{cite:2}}
  • self means "this particular object". Inside the class, self.name is this dog's name. When you call rex.learn("sit"), Python passes rex in as self automatically.{{cite:3}}
  • self.name and self.tricks are attributes: variables that belong to one object. Rex's tricks and Bella's tricks are separate lists.
  • learn and show_off are methods: functions that belong to the class, with self as their first parameter.

Try it: a click counter

Write a class Counter. A new counter starts with a count attribute of 0. Its method click() adds 1, and reset() puts it back to 0.

Getting "has no attribute 'count'"?

Inside __init__, write self.count = 0. Without self., count would be a local variable that's wiped when __init__ finishes (Lesson 12).

LeetCode's class Solution, explained

In real life

An exam paper with a box marked "Write your answer here". The box is just where the examiner knows to look. LeetCode's class Solution is that box.

LeetCode wraps every answer as a method of a class called Solution. Its test system makes an object, Solution(), and calls your method on it with each test input. That's why there's a self parameter you never use: every method gets one.{{cite:3}}

So writing for LeetCode means: write your function as you normally would, then indent it inside class Solution: and add self as the first parameter.

Solve it: LeetCode 1480, Running Sum

Inside class Solution, write runningSum(self, nums) that returns a list where each item is the total of all numbers up to and including that position. [1, 2, 3, 4] gives [1, 3, 6, 10].{{cite:4}}

A preview: objects that point to objects

In real life

A treasure hunt: each clue tells you something and also where to find the next clue. You can follow the whole chain from the first clue, one step at a time, until a clue says "the end".

An attribute can hold another object. A tiny class with a value and a link to the next one is the building block of a linked list, which you'll study in Lesson 27:

clues.py
class Node:
    def __init__(self, val, next=None):
        self.val = val
        self.next = next

third = Node("under the mat")
second = Node("in the oven", third)
first = Node("behind the clock", second)

clue = first
while clue is not None:
    print(clue.val)
    clue = clue.next
Showsbehind the clock in the oven under the mat

is not None asks "is there actually a node here?". The last node's next is None, so the loop stops there. Read that loop slowly; you'll write lots like it.

Check yourself

From memory, without scrolling up. A wrong answer here costs nothing: you just pick again.

1. What does self refer to inside a method?

In rex.learn("sit"), Python passes rex as self.

2. When does __init__ run?

Calling the class, like Dog("Rex"), creates an object and runs __init__ to set it up.

3. a = Counter() and b = Counter(), then a.click(). What is b.count?

Each object has its own attributes. Clicking a doesn't change b.

4. Why do LeetCode methods have a self parameter?

Every method's first parameter is the object it's called on. LeetCode calls Solution().yourMethod(...).
