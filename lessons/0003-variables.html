A name for a value

In real life

In a kitchen you might keep sugar in a jar with a label that says "sugar". You don't have to remember which jar is which: you read the label. When the sugar runs out, you refill the same jar and the label still works.

A variable is a labelled jar for a value. You choose the label (the variable's name), put a value in, and later use the name to get the value back.1

jars.py
age = 21
city = "Lagos"
print(age)
print(city)
Shows21 Lagos

The line age = 21 is called an assignment. Read it from right to left: "take the value 21 and store it under the name age". The = sign does not mean "is equal to" like in maths class. It means "store this".1

Notice that print(age) has no quotes. Without quotes, Python looks up the name and uses the value inside. With quotes, print("age") would just show the word age.

Variables inside expressions

Anywhere you could write a value, you can write a variable's name instead. Python swaps in the value when it works out the expression.

week.py
days = 7
hours_per_day = 24
hours_per_week = days * hours_per_day
print(hours_per_week)
Shows168

This is the same maths as Lesson 1, but now each number has a name that says what it means. Six months from now, days * hours_per_day is much easier to understand than 7 * 24.

A name that stores a value so you can use it later.

Changing what's inside

In real life

A scoreboard at a football match shows one number for each team. When a team scores, nobody builds a new scoreboard. They take the number that's there, add one, and put the new number up in the same place.

You can store a new value in a variable at any time. The old value is replaced. This is called reassigning the variable.1

score.py
score = 0
score = score + 10
score = score + 5
print(score)
Shows15

The line score = score + 10 looks strange if you read = as "equals". Read it right to left instead: work out score + 10 using the value that's in score now (0), get 10, then store that 10 back in score. The scoreboard way: read the old number, add, put the new number up.

Try it: three bonuses

A player starts with 0 points and earns a bonus of 10 points, three times. Using score = score + 10 three times, make score end at 30, then print it.

Why not just write score = 30?

That would work for this exact case, but real programs don't know the final number in advance: a game adds points whenever something happens. Practising score = score + 10 now pays off when we get to loops in Lesson 7.

Choosing good names

In real life

A label that says "stuff" on a jar is technically a label, but it doesn't help anyone. "Brown sugar" does. Names in code work the same way: Python accepts many names, but good ones tell the next reader what's inside.

Python has a few firm rules for variable names:1

  • Only letters, numbers and the underscore _. No spaces and no dashes.
  • It can't start with a number. player2 is fine; 2player is not.
  • Capital letters matter. score, Score and SCORE are three different variables.

And one habit that most Python programmers follow: names are lowercase, with underscores between words, like hours_per_day. This style is often called snake_case. Python's official style guide recommends it for variable names.3

NameAllowed?Why
total_costYesClear, and in snake_case
total costNoHas a space
total-costNoPython reads the dash as minus
2nd_placeNoStarts with a number
xYesAllowed, but says nothing about what's inside

Using a name before you've stored anything in it gives an error you already know from Lesson 1: NameError: name 'scroe' is not defined. Python has no jar with that label. Most of the time, it's a typo.

Joining text together

In real life

Think of fridge magnet words. You can push "Good" and "morning" together to make a sentence. But you can't stick a magnet word onto an actual number written in pen; they're different kinds of thing.

When + sits between two strings, it doesn't add: it joins them end to end. This is called concatenation.2

greet.py
name = "Ada"
greeting = "Good morning, " + name + "!"
print(greeting)
ShowsGood morning, Ada!

Notice the space inside "Good morning, ". Concatenation adds nothing extra, not even a space, so you include the spaces yourself.

Now the magnet problem. Mixing a string and a number with + gives an error:2

oops.py
age = 21
print("Age: " + age)
ShowsTypeError: can only concatenate str (not "int") to str

A TypeError means you used a value of the wrong kind. Python won't guess whether you wanted to add numbers or join text. The fix is a new function, str(). Think of a shop that writes a price on a sticky label: the price is a number, but the label is text you can stick next to other text. str() does the same, turning a number into text: str(21) gives "21". So "Age: " + str(age) shows Age: 21. Lesson 4 looks at text and number types properly.

1. After these lines run, what is in x? x = 5 then x = x + 2

2. Which variable name is allowed in Python?

Only letters, numbers and underscores, and it can't start with a number.

3. In age = 21, what does = do?

In Python, a single = is assignment: it stores the value on the right in the name on the left.

4. What happens when you run print("Score: " + 10)?

You can't join a string and a number with +. Use str(10) to turn the number into text first.
