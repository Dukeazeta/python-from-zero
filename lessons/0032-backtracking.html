Backtracking: try, undo, try again

Some problems ask for every possible combination: all the subsets, all the orderings, every way to make a total. Backtracking builds answers one choice at a time, and when a path is finished or hopeless, it undoes the last choice and tries the next.

Every path through the choices

In real life

Finding your way through a hedge maze: at each junction, pick a path. Hit a dead end? Walk back to the last junction and take the next path you haven't tried. Do that systematically and you'll eventually walk every route.

Backtracking is a depth-first search (Lesson 28) over choices rather than over a data structure.1 Picture a decision tree: at the root you've chosen nothing; each branch is one choice. Reaching the bottom of the tree means one complete answer. Backtracking walks every branch of that tree, recursively.

Almost every backtracking solution uses the same three-step template, with one shared list, path, holding the choices made so far:2

template.py
def backtrack(...):
    if the path is a complete answer:
        results.append(path[:])      # save a COPY
        return
    for choice in the choices available now:
        path.append(choice)          # 1. choose
        backtrack(...)               # 2. explore
        path.pop()                   # 3. un-choose (backtrack)

Two details that catch everyone:

  • path.pop() after the recursive call undoes the choice, so the next loop iteration starts from the same state. That's the "back" in backtracking.
  • Save path[:], not path. A slice makes a new copy of the list.3 Saving path itself saves a reference to the one shared list, which keeps changing, and ends up empty.

Subsets: take it or leave it

In real life

Choosing pizza toppings from mushroom, onion and pepper. For each topping you decide yes or no. Three yes/no decisions give 2 × 2 × 2 = 8 possible pizzas, including the plain one with nothing.

For subsets, the choice at each item is "include it or not". With n items that's 2n subsets, so any solution is O(2n) at least: there are simply that many answers to write out.4 Exponential problems like this usually come with small inputs (LeetCode 78 has at most 10 numbers).

One neat way: at position i, first explore with nums[i] added, then explore without it. When i reaches the end, the path is a complete subset.

LeetCode 78: Subsets

Return all subsets of nums (all numbers are different). Any order is fine.

Stuck? A hint

Four lines: path.append(nums[i]), backtrack(i + 1), path.pop(), backtrack(i + 1). The first call explores "with", the second "without".

Getting a list of empty lists?

You saved path instead of path[:]. Every saved answer is the same list, which is empty by the end.

Permutations: every ordering

In real life

Seating 3 guests in 3 chairs: anyone can take the first chair, then either of the 2 left takes the second, and the last person gets the last chair. 3 × 2 × 1 = 6 seating plans.

A permutation is an ordering of all the items. Now the choice at each step is "which unused item goes next?", so keep a set of items already in the path and skip those. Skipping choices that can't lead to a valid answer is called pruning. With n items there are n! (n factorial, Lesson 25) orderings: 6 for 3 items, 3,628,800 for 10.

LeetCode 46: Permutations

Return all orderings of nums (all different). Any order is fine.

Stuck? A hint

Base case: len(path) == len(nums), save a copy. Otherwise, for each n in nums not in used: append it and add it to used, call backtrack(), then undo both.

Challenge: making a total

LeetCode 39: find every combination of the given numbers that adds up to target, where each number can be used any number of times.6 [2, 2, 3] and [7] both make 7 from [2, 3, 6, 7].

Two ideas keep it correct and fast. To avoid listing [2, 2, 3] and [3, 2, 2] as different answers, only ever choose numbers from the current position onwards (pass a start index). To prune, stop as soon as the remaining total goes below zero: adding more can only make it worse.

LeetCode 39: Combination Sum

Return all unique combinations (each as a list) of candidates that sum to target. Numbers may repeat within a combination. Any order is fine.

Stuck? A hint

Base cases: remaining == 0 means save a copy; remaining < 0 means give up on this path. Loop for i in range(start, len(candidates)), and recurse with backtrack(i, remaining - candidates[i]): passing i, not i + 1, is what allows reusing the same number.

New words

Backtracking
Building answers one choice at a time, undoing the last choice to try the next.
Decision tree
A picture of all the choices: each branch one choice, each bottom a complete answer.
Permutation
One ordering of all the items. n items have n! of them.
Pruning
Skipping branches that can't lead to a valid answer.

Check yourself

From memory, without scrolling up. A wrong answer here costs nothing: you just pick again.

1. Why save path[:] rather than path?

There's only one path list. Without a copy, every saved answer points at it and changes with it.

2. How many subsets does a set of 5 different items have?

Each item is in or out: 2 × 2 × 2 × 2 × 2.

3. What does path.pop() after the recursive call do?

It restores the path to how it was before this choice: the backtrack step.

4. In Combination Sum, why recurse with i instead of i + 1?

Staying at i lets the next choice be the same number again. Starting at i, not 0, still prevents re-orderings.
