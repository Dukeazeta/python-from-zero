Graphs

Things and connections

In real life

A map of towns joined by roads. Some towns have many roads, some only one. You can drive round in a circle and end up where you started. There's no "top" town the way a tree has a root.

A graph is a set of vertices (also called nodes) joined by edges. Edges can be one-way, making a directed graph (like following someone on social media), or two-way, an undirected graph (like a friendship).1 A tree is a graph with no cycles and one root; general graphs can have both cycles and disconnected pieces.

The usual way to store one is an adjacency list: a dictionary from each vertex to a list of its neighbours.2 Problems often hand you a list of edges, so building the dictionary is step one:

roads.py
edges = [("Lagos", "Ibadan"), ("Ibadan", "Ilorin"), ("Lagos", "Abeokuta")]
graph = {}
for a, b in edges:
    graph.setdefault(a, []).append(b)
    graph.setdefault(b, []).append(a)     # undirected: both ways
print(graph["Lagos"])
Shows['Ibadan', 'Abeokuta']

graph.setdefault(a, []) gives the list for a, creating an empty one first if needed.

Exploring without going round in circles

In real life

Exploring a maze, you chalk an X on every junction you've been to. Arriving at an X, you know not to go that way again, or you'd walk the same loop forever.

DFS and BFS work on graphs just as on trees, with one addition: a visited set. Trees never lead back to a node you've seen; graphs with cycles do, so without the chalk marks you'd loop forever.3 Each vertex is visited once and each edge looked at once (twice if undirected), so both are O(V + E): vertices plus edges.4

explore.py
def dfs(graph, start, visited):
    visited.add(start)
    for neighbour in graph.get(start, []):
        if neighbour not in visited:
            dfs(graph, neighbour, visited)

A connected component is a group of vertices that can all reach each other. To count them: go through every vertex; each time you find one not yet visited, that's a new component, so count it and explore everything reachable from it.

Try it: count the groups of friends

People are numbered 0 to n - 1, and pairs lists who are friends. Return how many separate friend groups there are. Build an adjacency list, then count components with DFS.

Stuck? A hint

Write a small explore(person) function inside, like dfs above. Then loop over everyone: when someone isn't in visited, add 1 to groups and explore them.

A grid is a graph too

In real life

The paint bucket tool in a drawing app: click one pixel, and the colour spreads to every touching pixel of the same colour, and from those to theirs, until it reaches a different colour.

Many graph problems never mention a graph. In a grid (Lesson 16), each cell is a vertex, and its neighbours are the cells up, down, left and right. The bounds checking you wrote for the Game of Life applies directly. Instead of a separate visited set, you can often change the cell itself (repaint it, or turn land into water) so you never count it twice.

LeetCode 733: Flood Fill

Starting at image[sr][sc], repaint it and every connected cell of the same original colour (up, down, left, right) with color. Return the image.5

Stuck? A hint

Inside fill: return straight away if (r, c) is off the grid or isn't the start colour. Otherwise paint it, then call fill on the four neighbours.

LeetCode 200: Number of Islands

grid holds "1" for land and "0" for water (strings). An island is land connected up, down, left or right. Count the islands.6 It's the friend-groups problem on a grid: for each unvisited land cell, count it and sink the whole island.

Stuck? A hint

Write a sink(r, c) like fill, turning "1" into "0". Then loop over every cell: on a "1", add one island and sink it so its cells are never counted again.

Very big grids

Recursion depth is limited to about 1,000 calls (Lesson 25). For a huge island, a BFS with a deque (Lesson 29) avoids that limit: queue the starting cell, and queue each neighbouring land cell as you sink it. LeetCode's tests pass either way.

New words

Graph
Vertices (things) joined by edges (connections).
Directed / undirected
Edges that go one way / both ways.
Adjacency list
A dictionary from each vertex to its list of neighbours.
Connected component
A group of vertices that can all reach each other.
O(V + E)

Check yourself

From memory, without scrolling up. A wrong answer here costs nothing: you just pick again.

1. Why does graph DFS need a visited set when tree DFS didn't?

A cycle leads back to a vertex you've seen; without marking it, you'd loop forever.

2. In an undirected adjacency list, the edge A-B is stored how?

Two-way edges are recorded from both ends.

3. In Number of Islands, which cells count as neighbours?

The problem connects land horizontally and vertically only, so diagonal land is a separate island.

4. The time cost of BFS on a graph with V vertices and E edges?

Each vertex is visited once and each edge checked a constant number of times.
