Project: Snake in the terminal

A real-time game: the snake keeps moving whether you press a key or not, grows when it eats, and dies if it hits a wall or itself. You'll test the game logic here, then drive it with the keyboard on your computer using a terminal-graphics library.

A snake is a list of squares

In real life

A conga line moving across a dance floor: the leader steps forward, and everyone else takes the place of the person in front. From above, it looks like the whole line moved one step, but really a new square was taken at the front and one was given up at the back.

This project is from Robert Heaton's series in the Project Based Learning list.15 The key design choice, which he stresses, is keeping the game logic (where the snake is, what happens next) separate from the display (drawing it on screen). The logic is plain Python you can test here; the display comes at the end.

The snake is a list of (row, col) tuples, head first: [(5, 4), (5, 3), (5, 2)] is a snake of length 3 facing right. Directions are small steps: "UP" is one row up, (-1, 0); "RIGHT" is one column right, (0, 1).

Moving one tick: work out the new head, put it at the front, and remove the last square, unless the new head lands on the food. Then the tail stays, and the snake is one square longer.

Milestone 1: move and grow

Write move(snake, direction, food). Return a tuple (new_snake, ate): the snake after one tick, and True if it ate the food. Don't change the list you were given; build a new one.

Stuck? A hint

[new_head] + snake is a new list with the head added. If it ate, return that. Otherwise drop the last square with a slice: [new_head] + snake[:-1].

Dying, and no U-turns

The snake dies if its head goes off the board or onto its own body. It also shouldn't be able to reverse straight back into itself: pressing left while moving right should be ignored.1

Milestone 2: game over?

Write is_dead(snake, height, width): True if the head is outside rows 0 to height - 1 or columns 0 to width - 1, or if the head is somewhere in the rest of the body.

Milestone 3: no reversing

Write is_opposite(new, current) returning True if the two directions are opposites (UP and DOWN, or LEFT and RIGHT).

A tidy way

A dictionary from each direction to its opposite, then return opposites[new] == current.

Make it real-time

In real life

A metronome ticks whether or not you play a note. Snake works the same way: every tick the snake moves, and pressing a key only changes the direction for the next tick.

input() waits for Enter, which is no good for a game that keeps moving. The curses library takes over the terminal window: it reads single key presses, can wait a set time for one and carry on if none comes, and draws characters anywhere on the screen.2 Windows needs one extra package for it, windows-curses, which you'll install in a virtual environment (Lesson 18).4

  3. Create game.py, the display and keyboard part:

    game.py
    import curses
import random

from snake import move, is_dead, is_opposite

HEIGHT, WIDTH = 15, 30
KEYS = {curses.KEY_UP: "UP", curses.KEY_DOWN: "DOWN",
        curses.KEY_LEFT: "LEFT", curses.KEY_RIGHT: "RIGHT"}


def place_food(snake):
    while True:
        spot = (random.randrange(HEIGHT), random.randrange(WIDTH))
        if spot not in snake:
            return spot


def draw(screen, snake, food, score):
    screen.erase()
    screen.addstr(0, 0, "+" + "-" * WIDTH + "+")
    for r in range(HEIGHT):
        screen.addstr(r + 1, 0, "|" + " " * WIDTH + "|")
    screen.addstr(HEIGHT + 1, 0, "+" + "-" * WIDTH + "+")
    screen.addstr(food[0] + 1, food[1] + 1, "*")
    for r, c in snake:
        screen.addstr(r + 1, c + 1, "O")
    screen.addstr(HEIGHT + 2, 0, f"Score: {score}   (arrow keys to steer, q to quit)")
    screen.refresh()


def main(screen):
    curses.curs_set(0)          # hide the cursor
    screen.timeout(120)         # getch waits at most 120 ms: one tick
    snake = [(7, 10), (7, 9), (7, 8)]
    direction = "RIGHT"
    food = place_food(snake)
    score = 0
    while True:
        draw(screen, snake, food, score)
        key = screen.getch()    # -1 if no key was pressed this tick
        if key == ord("q"):     # ord() turns a letter into the number getch() reports for that key
            break
        if key in KEYS and not is_opposite(KEYS[key], direction):
            direction = KEYS[key]
        snake, ate = move(snake, direction, food)
        if is_dead(snake, HEIGHT, WIDTH):
            break
        if ate:
            score += 1
            food = place_food(snake)
    return score


if __name__ == "__main__":
    final = curses.wrapper(main)
    print(f"Final score: {final}")

    curses.wrapper(main) sets the terminal up, runs main, and always puts the terminal back to normal afterwards, even if your code crashes.2 screen.timeout(120) is the metronome: getch() returns a key if one is pressed within 120 milliseconds, or -1 if not, and the loop moves on either way.3

Check yourself

From memory, without scrolling up. A wrong answer here costs nothing: you just pick again.

1. When the snake eats, what's different about the move?

Adding a head and keeping the tail makes it one square longer.

2. Why use screen.timeout(120) rather than waiting for a key?

getch gives up after 120 ms and returns -1, so every loop is one tick of the game.

3. Why keep the game logic in a separate file from the curses code?

Plain functions in, plain values out: easy to test, as you did on this page.

4. How does is_dead detect the snake biting itself?

snake[0] in snake[1:] checks whether the head shares a square with any body part.
