Sorting a hand of cards

In real life

Picking up playing cards one at a time: each new card gets slid left past the bigger ones until it sits in the right place among the cards you already hold. That's easy with 7 cards, but with a whole shoe of 300, each new card has to be compared with lots of others.

That's insertion sort: take each item and move it left until it's in place among the sorted items before it.1 In the worst case, each of the n items slides past up to n others: O(n²). Most "obvious" sorting methods are O(n²) for the same reason: they compare items close to every other item.

Try it: insertion sort

Finish insertion_sort(items) so it sorts the list in place and returns it. For each position i, take items[i] and shift bigger items in front of it one place right until you find its spot.

Merge sort: divide and conquer

In real life

A teacher with 64 exam papers to put in name order gives half to each of two assistants, who each split theirs again, until everyone holds one paper (already "sorted"). Then pairs combine: two neat piles merge into one by repeatedly taking whichever top paper comes first. Piles double in size until one sorted stack is left.

Merge sort is a divide and conquer algorithm: split the list in half, sort each half (recursively, Lesson 25), then merge the two sorted halves.2 The base case: a list of 0 or 1 items is already sorted.

The merge step is two pointers (Lesson 21): one at the start of each sorted half. Repeatedly take the smaller of the two front items, and when one half runs out, add the rest of the other.

Why it's fast: halving gives about log n levels of splitting, and each level does O(n) work merging, so O(n log n) in total.2 For a million items that's about 20 million steps instead of a trillion.

Write merge(a, b) that takes two sorted lists and returns one sorted list with all their items, using two pointers (no sorted()).

In real code: sorted() and key

In real life

A class register can be sorted by surname, by age, or by exam score. The students are the same; what changes is which detail you compare.

In real code and in most interviews (unless they ask you to implement one), use Python's built-in sort, which is O(n log n).3 sorted(items) returns a new sorted list; items.sort() sorts the list in place and returns None.

The key argument says what to compare: a function applied to each item. reverse=True sorts biggest first.

register.py
words = ["banana", "Kiwi", "apple", "fig"]
print(sorted(words, key=len))
print(sorted(words, key=str.lower))

def by_score(student):
    return student[1]

students = [("Ada", 72), ("Bo", 91), ("Chi", 72)]
print(sorted(students, key=by_score, reverse=True))
Shows['fig', 'Kiwi', 'apple', 'banana'] ['apple', 'banana', 'fig', 'Kiwi'] [('Bo', 91), ('Ada', 72), ('Chi', 72)]

Notice Ada stays before Chi: they tie on 72, and Python's sort is stable, meaning items that compare equal keep their original order.4 To sort by two things, return a tuple from the key: key=by_age_then_name returning (age, name) sorts by age, and by name where ages tie.

Try it: a leaderboard

Challenge: merging from the back

LeetCode 88 gives two sorted lists, but the first one, nums1, has extra zeros on the end making room for the second, and you must merge in place into nums1.5 Merging from the front would overwrite items you haven't used yet. The trick: fill from the back. Compare the largest remaining items of each list and write the bigger one into the last empty slot.

LeetCode 88: Merge Sorted Array

nums1 has m real items followed by n zeros; nums2 has n items. Change nums1 in place so it holds all m + n items sorted. Don't return anything.

Stuck? A hint

Loop while j >= 0 (items of nums2 left to place). If nums1 still has items and its biggest is bigger, write it at write; otherwise write nums2[j]. Move the pointer you used, and write, one step left. Leftover nums1 items are already in place.

New words

Divide and conquer
Split a problem into halves, solve each, and combine the answers.
Merge sort
Sort each half recursively, then merge the two sorted halves. O(n log n).
Key function
A function telling sorted() what to compare for each item.
Stable sort
A sort that keeps equal items in their original order.

1. What is the Big O of merge sort?

About log n levels of halving, with O(n) merging work on each level.

2. What does nums.sort() return?

list.sort() sorts in place and returns None. sorted() is the one that returns a new list.

3. What does sorted(["bb", "a", "ccc"], key=len) give?

key=len compares the lengths, but the items themselves are what's returned.

4. In Merge Sorted Array, why fill nums1 from the back?

The spare slots are at the end, so writing there never destroys an item you still need.
