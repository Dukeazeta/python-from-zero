Python reads your code and works out what it means. Real programming languages start with the same two steps: splitting the text into pieces, then working out how they fit together.

Teaching a computer to read maths

In real life

Reading a sentence happens in two steps you rarely notice. First you split the letters into words ("the", "cat", "sat"). Then you work out how the words fit together: who did what. A program that understands a language does the same two steps, just much more strictly.

An interpreter is a program that reads text written in some language and carries it out. Python itself is one. This project follows Ruslan Spivak's series "Let's Build A Simple Interpreter", from the Project Based Learning list, through its first six parts: a calculator that understands + - * /, order of operations and brackets.15

  1. The lexer (or tokenizer) splits text into tokens: meaningful pieces like "the number 12" or "a plus sign", skipping spaces.1
  2. The parser reads the tokens following the rules of the language, called its grammar, and works out the answer.

Step 1: characters into tokens

Each token here is a tuple: its kind and its value. "12 + 3" becomes [("INT", 12), ("PLUS", "+"), ("INT", 3), ("EOF", None)]. The final EOF ("end of file") token marks the end, so the parser knows when to stop.1 A number can be several digits long, so keep reading digits until a non-digit appears.

Milestone 1: tokenize

Write tokenize(text). Kinds: INT (value is the whole number), PLUS, MINUS, MUL, DIV, LPAREN, RPAREN (value is the character), and a final ("EOF", None). Skip spaces. Any other character: raise ValueError(f"Unexpected character: {ch}").

Reading a whole number

When ch.isdigit(), remember start = i, then move i forward while the characters are digits. int(text[start:i]) is the number. In that branch, i has already moved past it, so don't add 1 again (use if / elif branches, each moving i itself).

Step 2: a grammar that knows the order of operations

In real life

A shopping receipt: the total is a sum of lines; each line is a quantity times a price; and a "price" might be a bundle in brackets that you work out first. Sums are made of products, products are made of single items or bracketed bundles. That nesting is exactly how maths precedence works.

Ruslan writes the grammar as three rules, each built from the next:34

grammar.txt
expr   : term   ((PLUS | MINUS) term)*
term   : factor ((MUL | DIV) factor)*
factor : INT | LPAREN expr RPAREN

Read * as "zero or more times" and | as "or". An expr is terms added or subtracted; a term is factors multiplied or divided; a factor is a number or a whole expression in brackets. Because term sits inside expr, multiplications are finished before additions see them: precedence falls out of the shape. And because factor refers back to expr, brackets can nest as deep as you like.

A recursive descent parser turns each rule into one method.3 A helper, eat(kind), checks the current token is the kind expected and moves on, or raises an error if it isn't. Each rule's loop handles a chain like 7 - 3 - 2 from left to right, so it means (7 - 3) - 2.2 In this calculator / is whole-number division, //, so every answer stays an int.

Milestone 2: the parser

Finish factor, term and expr. calc(text) is already written: it parses one expr and then insists the next token is EOF, so leftover tokens like the 3 in "2 3" are an error. tokenize is already written for you.

Hint 1: factor

If the current token is LPAREN: eat it, get value = self.expr(), eat RPAREN, return value. Otherwise return the number: self.eat("INT")[1] (eat returns the token, and [1] is its value). If it isn't an INT, eat raises the error for you.

Hint 2: term and expr

term: value = self.factor(), then while self.current()[0] in ("MUL", "DIV"): eat the operator and combine value with the next self.factor(). expr is the same shape one level up, with term, PLUS and MINUS.

Your own language prompt

The Python shell from Lesson 2 is a REPL: Read a line, Evaluate it, Print the result, Loop. Yours is a few lines.1

  1. Set up projects/calculator with git init -b main, and put SYMBOLS, tokenize, Parser and calc in calc.py.

  2. Add the loop at the bottom:

    calc.py (the end)
    def repl():
    print("Calculator. Type an expression, or quit to leave.")
    while True:
        text = input("calc> ").strip()
        if text == "quit":
            break
        if not text:
            continue
        try:
            print(calc(text))
        except ValueError as error:
            print(f"Error: {error}")
        except ZeroDivisionError:
            print("Error: division by zero")


if __name__ == "__main__":
    repl()

    except ValueError as error keeps the error so you can show its message (Lesson 15).

  3. Run it with pythonpython3 calc.py and type 2 + 3 * (4 - 1).

    Paste what it printed for 2 + 3 * (4 - 1):

    Correct: 3 times 3 first, then add 2. Your parser respects precedence and brackets.

    If you got 15, multiplication isn't binding tighter than addition: check that expr calls term, and term calls factor.

Make it yours (pick at least one)

  • Negative numbers: let a factor be a minus sign followed by another factor, so -3 + 5 and 2 * -(1 + 1) work. (That's Ruslan's part 7 and 8 territory.)
  • Variables: support x = 5 then x * 2, storing names in a dictionary.
  • Show the tokens: a :tokens 2+3 command that prints the token list, which makes debugging much easier.

Then write the README (include the grammar), commit, and push as python-calculator-interpreter.

Check yourself

From memory, without scrolling up. A wrong answer here costs nothing: you just pick again.

1. What does the lexer produce?

It groups characters into meaningful pieces; the parser does the rest.

2. Why does 2 + 3 * 4 give 14 and not 20?

expr asks term for its pieces, and term has already done the multiplication.

3. What does eat("RPAREN") do if the current token is INT?

eat insists on the expected kind; anything else is a syntax error.

4. What does REPL stand for?

Read a line, work it out, show the result, and go round again.
