Dynamic programming 1: remember, don't repeat

Remember the painfully slow Fibonacci from Lesson 25? It kept solving the same small problems over and over. Dynamic programming fixes that by remembering each answer the first time. It starts with one simple idea.

Write the answer down the first time

In real life

Someone asks you "what's 37 × 48?" You work it out on paper: 1776. Five minutes later they ask again. You don't redo the multiplication; you look at what you wrote down. Dynamic programming works the same way.

Recursive Fibonacci was slow because fib(5) calls fib(4) and fib(3), and fib(4) calls fib(3) again, and so on: the same subproblems (smaller versions of the problem) get solved many times. When that happens, the problem has overlapping subproblems, and dynamic programming (DP) applies: solve each subproblem once and store the answer.1

The quickest way is memoisation: keep a dictionary (the cache) from input to answer. Before computing, check the cache; after computing, store the result.1 This is called top-down DP, because you start from the big question and recurse down.

fast_fib.py
cache = {}

def fib(n):
    if n < 2:
        return n
    if n in cache:                  # seen it before? just look it up
        return cache[n]
    cache[n] = fib(n - 1) + fib(n - 2)
    return cache[n]

print(fib(80))
Shows (instantly)23416728348467685

Each fib(k) is now computed once, so the whole thing is O(n) instead of O(2ⁿ). fib(80) without the cache would take longer than a human lifetime.

Find the recurrence, then build up

In real life

Climbing stairs one or two steps at a time. How many different ways are there to reach step 10? Think about your very last move: you arrived either from step 9 (a single step) or from step 8 (a double step). So the ways to reach 10 are the ways to reach 9 plus the ways to reach 8.

That sentence is a recurrence relation: the answer for n written in terms of answers for smaller n.3 Finding it is the hard part of most DP problems. Here it's ways(n) = ways(n - 1) + ways(n - 2), with ways(1) = 1 and ways(2) = 2. (Yes, it's Fibonacci in disguise.)

Instead of recursing down, you can also start from the smallest cases and fill in a list upwards: tabulation, or bottom-up DP. No recursion, so no recursion limit.1

table.txt
step:   1  2  3  4  5
ways:   1  2  3  5  8      each = the two before it added

LeetCode 70: Climbing Stairs

Return the number of distinct ways to climb n steps, taking 1 or 2 steps at a time. Build it bottom-up; it must handle n = 45 instantly.

You often only need the last two

Each entry only looks at the two before it, so you don't need the whole list: two variables, rolled forward, give O(1) space. Get it right with a list first, then shrink it.

DP for the cheapest way

DP isn't only for counting. LeetCode 746 gives a cost for standing on each step; you can start on step 0 or 1 and climb 1 or 2 steps at a time. What's the cheapest way to get past the top?4 Same reasoning about the last move, with min instead of +: the cheapest cost to reach step i is the cheaper of arriving from i - 1 or from i - 2, each plus that step's cost.

LeetCode 746: Min Cost Climbing Stairs

Return the minimum cost to reach the top (one step past the last index).

Stuck? A hint

Starting on step 0 or 1 is free, so best[0] and best[1] stay 0. For i from 2 to n: best[i] = min(best[i-1] + cost[i-1], best[i-2] + cost[i-2]). You pay a step's cost when you step off it.

Challenge: take it or skip it

In real life

Picking fruit from a row of trees where an alarm goes off if you pick from two neighbouring trees. At each tree you decide: pick here (so you must have skipped the previous one), or skip it (and keep whatever you had by the previous tree).

LeetCode 198 is the classic version: houses in a row with money in each, and you can't rob two neighbours.5 For each house, the best total up to here is the better of two options: rob it (its money plus the best up to two houses back) or skip it (the best up to the previous house). That "take it or skip it" choice comes up in many DP problems.

LeetCode 198: House Robber

Return the most money you can take without robbing two neighbouring houses. Try it with two variables (O(1) space): prev2 is the best up to two houses back, prev1 the best up to the previous house.

Stuck? A hint

Inside the loop: current = max(prev1, prev2 + money) (skip it, or take it). Then roll forward with the tuple trick from Lesson 14: prev2, prev1 = prev1, current.

New words

Dynamic programming (DP)
Solving overlapping subproblems once each and reusing the answers.
Memoisation
Caching each function result the first time it's computed (top-down).
Tabulation
Filling a table from the smallest cases upwards (bottom-up).
Recurrence relation
A rule giving the answer for n in terms of answers for smaller inputs.

Check yourself

From memory, without scrolling up. A wrong answer here costs nothing: you just pick again.

1. What makes a problem suitable for dynamic programming?

Overlapping subproblems are what make storing answers pay off.

2. What's the difference between memoisation and tabulation?

Both solve each subproblem once; they differ in direction.

3. With 1 or 2 steps at a time, how many ways are there to climb 4 steps?

ways(4) = ways(3) + ways(2) = 3 + 2.

4. In House Robber, the best total at a house is the larger of?

Taking it forbids the neighbour, so it pairs with the best up to two houses back.
