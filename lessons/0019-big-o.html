Big O: how code slows down as data grows

Two programs can give the same answer while one takes a second and the other takes all day. Big O is the language programmers use to describe that difference, and interviewers often ask about it.

Same answer, very different wait

In real life

You need the word "python" in a paper dictionary. Method one: read every page from the start until you find it. Method two: open it in the middle, see you're at "m", jump halfway into the second half, and keep halving. Both find the word. For a thin dictionary the difference doesn't matter. For a 2,000-page one, method one could take hours and method two about a dozen flips.

An algorithm is a step-by-step method for solving a problem. To compare algorithms, we don't time them with a stopwatch (that depends on the computer). We ask: as the input gets bigger, how fast does the number of steps grow?1 The size of the input is called n: the number of items in the list, the length of the string.

Big O notation is the shorthand for that growth. "This is O(n)" (said "oh of n") means "the steps grow in step with n: double the data, double the work".1

O(n²)quadraticEveryone at a party shaking hands with everyone else1,000,000,000,000

Look at the last column. At a million steps a second, O(n) finishes in one second. O(n²) would take about eleven days. That's why interviewers care: on big inputs, the shape matters far more than how fast the computer is.1

Why is halving O(log n)? Each step throws away half of what's left. A million items halve to one item in about 20 steps, because 2 multiplied by itself 20 times is just over a million.4

Working out the Big O of code

In real life

Estimating a journey, you care whether it's a walk to the shop or a drive across the country. Whether you stop for one minute or two at the traffic lights doesn't change the answer.

Three rules cover most code:

  1. A loop over n items is O(n). Each step inside the loop that takes a fixed amount of work counts as O(1).
  2. Nested loops multiply. A loop over n inside a loop over n is n times n: O(n²) (remember the nested loops in Lesson 16). Loops one after another add: O(n) + O(n) is still O(n).
  3. Drop constants and smaller parts. 3n + 10 steps is O(n). n² + n is O(n²). Big O only describes the shape of the growth when n is huge, where those details stop mattering.1

We also usually describe the worst case: searching a list for something that isn't there checks every item, so it's O(n), even though sometimes you get lucky on the first item.

The same idea applies to memory, called space complexity: a function that builds a set of all n items uses O(n) extra space; one that only keeps a running total uses O(1).

Hidden loops

Some single lines hide a loop. The big one for interviews:23

  • x in my_list checks items one by one: O(n).
  • x in my_set and key in my_dict jump straight to the spot: O(1) on average.
  • my_list.append(x) is O(1), but my_list.insert(0, x) (put x at the front) and my_list.pop(0) (take the first item out) shift every other item along: O(n).
  • sorted(my_list) is O(n log n).

So a loop containing if x in some_list is secretly a nested loop: O(n²). Swap the list for a set and it becomes O(n). You'll use that speed-up often in interview answers.

Your first speed-up

Here's a correct but slow way to check a list for duplicates: compare every item with every later item. Two nested loops over n: O(n²).

slow.py
def has_duplicate_slow(items):
    for i in range(len(items)):
        for j in range(i + 1, len(items)):
            if items[i] == items[j]:
                return True
    return False

On a list of 20,000 different numbers, that's about 200 million comparisons. The "seen before?" set from Lesson 14 does it in one pass: O(n) time, using O(n) extra space for the set.

New words

Algorithm
A step-by-step method for solving a problem.
Big O
How an algorithm's steps grow as the input size n grows.
O(1), O(n), O(n²)
Constant, linear and quadratic growth.
O(log n)
Growth when each step halves the work left.
Space complexity
How the extra memory an algorithm uses grows with n.
