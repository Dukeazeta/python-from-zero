Trees and depth-first search

A tree is a linked list where each node can point to two others instead of one. Family trees, folders on your computer, the structure of a web page: all trees. Recursion, from Lesson 25, does most of the work.

Branching instead of a chain

In real life

A family tree drawn upside down: one ancestor at the top, their children below, and their children's children below that. Or the folders on your computer: a drive holds folders, which hold folders, which hold files at the bottom.

A tree is made of nodes joined by links, starting from one node at the top called the root. In a binary tree, each node has at most two children, left and right. A node with no children is a leaf. The depth (or height) of a tree is the number of nodes on the longest path from the root down to a leaf.12

tree.txt
        3          <- root
       / \
      9   20
         /  \
        15   7     <- 9, 15 and 7 are leaves
depth = 3 (3 -> 20 -> 15)

LeetCode writes trees as a list read level by level, with None for a missing child: the tree above is [3, 9, 20, None, None, 15, 7]. In the exercises, build_tree turns such a list into TreeNode objects, and tree_to_list turns a tree back into one.

Every subtree is a tree

In real life

To count everyone in a family tree, the head of the family can say: "it's me, plus everyone in my first child's branch, plus everyone in my second child's branch." Each child answers the same question about their own branch. Someone with no children just says "one".

A node's left child is the root of a smaller tree (its subtree), and so is its right child. So almost every tree problem has the same recursive shape:1

shape.py
def solve(node):
    if node is None:              # base case: the empty tree
        return ...
    left_answer = solve(node.left)
    right_answer = solve(node.right)
    return ...combine node.val, left_answer and right_answer...

Going all the way down one branch before coming back up to try the next is called depth-first search (DFS). It visits each node once: O(n) time. The extra space is the call stack, as deep as the tree is tall.

LeetCode 104: Maximum Depth of Binary Tree

Return the depth of the tree. The empty tree (None) has depth 0. A node's depth is 1 plus the deeper of its two subtrees.4

Stuck? A hint

Two lines: if root is None, return 0. Otherwise return 1 + max(left depth, right depth), where each depth is self.maxDepth(...) of a child.

LeetCode 100: Same Tree

Return True if trees p and q have the same shape and the same values.5

Stuck? A hint

Base cases first: both None means same; exactly one None, or different values, means not the same. Otherwise both left subtrees must match and both right subtrees must match.

LeetCode 226: Invert Binary Tree

Mirror the tree: swap every node's left and right children, all the way down, and return the root.6

Three orders for visiting a tree

In real life

Reading out a family tree, you could announce each parent before their children (top-down), or the children before the parent (bottom-up), or the left-hand family, then the parent, then the right-hand family.

A depth-first traversal visits every node, in one of three standard orders depending on when you record the node itself:3

  • Preorder: node, then left subtree, then right subtree.
  • Inorder: left subtree, then node, then right subtree.
  • Postorder: left subtree, then right subtree, then node.

For the tree [1, 2, 3] (1 at the root, 2 on the left, 3 on the right): preorder is 1, 2, 3; inorder is 2, 1, 3; postorder is 2, 3, 1.

LeetCode 94: Binary Tree Inorder Traversal

Return the values in inorder (left, node, right).7 A helper function inside the method can append to one shared list.

A function inside a function?

Yes, that's allowed. visit can see result because it's defined inside the method. Base case: if node is None: return. Then visit left, append node.val, visit right.

Notice the last test: that tree is a binary search tree, where everything on a node's left is smaller and everything on its right is bigger. Inorder traversal of a binary search tree comes out sorted. That property is behind many tree interview questions.

New words

Binary tree
A tree where each node has at most a left and a right child.
Root / leaf
The top node / a node with no children.
Subtree
A node and everything below it: itself a tree.
Depth-first search (DFS)
Exploring all the way down one branch before backing up to the next.
Preorder / inorder / postorder
When the node is visited: before, between, or after its subtrees.
