Git and GitHub: save points and a portfolio

Before you build portfolio projects, you need somewhere to keep them where employers can see them, and a safety net so a bad change never costs you your work. Git gives you save points; GitHub puts them online.

Save points for your code

In real life

A video game with save points. Before the boss fight, you save. If it goes badly, you load the save instead of starting the whole game again. And you can look back at a list of every save, each with a note like "before the boss".

Version control keeps a history of your project, so you can see what changed, when, and go back. Git is the version control tool almost every software team uses.1 A folder whose history Git tracks is a repository (or "repo"). Each save point is a commit: a snapshot of your files plus a short message saying what changed.

Saving happens in two steps.1 First you choose which changes go in the next snapshot, called staging (git add). Then you take the snapshot (git commit). Like packing a box before sealing it: you decide what goes in, then tape it shut with a label.

  1. Check Git is installed.

    Terminal
    > git --version% git --version$ git --version
    Shows something likegit version 2.55.0.windows.2

    Paste what your terminal showed:

    Git is installed.

    If Windows doesn't recognise git, install it from git-scm.com (the default options are fine), then open a new terminal window.If a box offers to install the command line developer tools, accept it: that installs Git. Then open a new terminal window.If it says command not found, install Git with your package manager (on Ubuntu: sudo apt install git).

  2. Tell Git who you are (once per computer; it labels your commits). Use the email you'll use for GitHub:

    Terminal
    > git config --global user.name "Your Name"% git config --global user.name "Your Name"$ git config --global user.name "Your Name"
> git config --global user.email "you@example.com"% git config --global user.email "you@example.com"$ git config --global user.email "you@example.com"

  3. Make a project and turn it into a repository. Each portfolio project gets its own folder and its own repo. From your course folder:

    Terminal
    ...python-course> mkdir projects\hello-gitpython-course % mkdir -p projects/hello-gitpython-course $ mkdir -p projects/hello-git
...python-course> cd projects\hello-gitpython-course % cd projects/hello-gitpython-course $ cd projects/hello-git
...hello-git> git init -b mainhello-git % git init -b mainhello-git $ git init -b main
    ShowsInitialized empty Git repository in .../hello-git/.git/

    Git keeps the whole history in a hidden .git folder inside the project.2 -b main names the main line of history "main", which is what GitHub expects.

Your first commit

  1. Make a file in the project, hello.py, containing print("hi"). Then ask Git what it sees:

    Terminal
    ...hello-git> git statushello-git % git statushello-git $ git status
    ShowsOn branch main No commits yet Untracked files: (use "git add <file>..." to include in what will be committed) hello.py

    "Untracked" means Git sees the file but isn't keeping its history yet. git status is the command you'll run most; it always tells you where you are and often suggests what to do next.3

  2. Ignore what shouldn't be saved. Virtual environments (Lesson 18) and Python's cache folders don't belong in a repo; anyone can recreate them. Make a file called .gitignore containing:

    .gitignore
    .venv/
__pycache__/

    Git skips anything matching a line in .gitignore.3

  3. Stage and commit. git add . stages everything in the folder (the dot means "here"). -m gives the commit message:

    Terminal
    ...hello-git> git add .hello-git % git add .hello-git $ git add .
...hello-git> git commit -m "First commit"hello-git % git commit -m "First commit"hello-git $ git commit -m "First commit"
...hello-git> git log --onelinehello-git % git log --onelinehello-git $ git log --oneline
    Shows something like[main (root-commit) a60018f] First commit 2 files changed, 3 insertions(+) create mode 100644 .gitignore create mode 100644 hello.py a60018f First commit

    You may also see warnings about "LF will be replaced by CRLF". That's Git noting the different ways Windows and other systems end lines; it's harmless. The 7 characters like a60018f are the start of the commit's unique ID.

    Paste what git log --oneline showed:

    Your first save point exists. From now on, commit whenever something works.

    Run git status: if files are listed under "Changes to be committed", the commit didn't happen; if under "Untracked", run git add . first.

A good commit message says what the change does, in a few words: "Add neighbour counting", "Fix crash on empty board". Commit small and often: each commit is a save point you can return to.

GitHub: your code, online

In real life

Git is your notebook of save points, kept at home. GitHub is a public library shelf where you can put a copy. Employers can browse it, and if your laptop dies, your work is still there.

GitHub is a website that hosts Git repositories. Your GitHub profile becomes a portfolio: recruiters often look at it.4 A copy of your repo somewhere else is called a remote; sending your commits to it is a push.

  1. Make a GitHub account at github.com if you don't have one. Choose a professional username; it will appear in your portfolio links.

  2. Create an empty repository on GitHub: the + menu, then New repository. Name it hello-git, make it Public, and don't tick the options to add a README or .gitignore (your local repo already has files, and those options would create a conflicting first commit).5

  3. Connect and push. GitHub shows the commands on the new repo's page; they look like this, with your username:

    Terminal
    ...hello-git> git remote add origin https://github.com/YOUR-USERNAME/hello-git.githello-git % git remote add origin https://github.com/YOUR-USERNAME/hello-git.githello-git $ git remote add origin https://github.com/YOUR-USERNAME/hello-git.git
...hello-git> git push -u origin mainhello-git % git push -u origin mainhello-git $ git push -u origin main

    origin is the usual nickname for your GitHub copy.5 The first push may open a browser window asking you to sign in to GitHub; that's Git's credential helper, and you only do it once. Refresh the GitHub page: your files are there.

The loop from now on

Edit, then git add ., then git commit -m "...", then git push. After the first push, plain git push is enough.

Every project in the next five lessons gets its own repo, pushed to GitHub, with a README.md file: a short description that GitHub shows on the repo's front page.4 Write what the project does, how to run it, and what you learned. That page is what an employer reads first.

New words

Repository (repo)
A project folder whose history Git tracks.
Commit
A saved snapshot of the project, with a message.
Staging
Choosing which changes go into the next commit (git add).
.gitignore
A file listing things Git should not track.
Remote / push
A copy of the repo elsewhere / sending your commits to it.

Check yourself

From memory, without scrolling up. A wrong answer here costs nothing: you just pick again.

1. What's the right order to save your work?

Stage the changes, take the snapshot, then send it to GitHub.

2. Why put .venv/ in .gitignore?

Environments are rebuilt from a list of packages; committing them bloats the repo.

3. Which command tells you what Git currently sees?

status shows the branch, staged changes, unstaged changes and untracked files.

4. What does origin usually mean?

It's the conventional nickname for the remote you push to.
